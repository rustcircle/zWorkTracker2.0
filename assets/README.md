## Rule

Regenerate with the same script, never by hand. Change `logo.svg` (or a tray SVG) only together with the owner,
then run `build-icons.py` and copy its outputs here; never edit a PNG, `.ico` or `.icns` directly. When 1.x
regenerates its icons, copy the new files from 1.x again and update the table above.

## Where build-icons.py writes, and where that lands here

The script is unchanged from 1.x, so it still writes the 1.x layout relative to the repo root
(`REPO = assets/logo/../..`):

| `build-icons.py` writes (1.x path) | 2.0 path |
|---|---|
| `src-tauri/icons/32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.png`, `icon.ico`, `icon.icns`, `tray-idle.png`, `tray-running.png` | `assets/icons/` (same names) |
| `site/assets/logo.svg`, `favicon.svg`, `icon-64.png`, `apple-touch-icon.png` | `site/assets/` (same paths; at the time of copying they were already byte-identical to 1.x) |

Run in this repo from the root with `uv run assets/logo/build-icons.py`, it creates `src-tauri/icons/` (a 1.x path
that 2.0 does not use) and overwrites `site/assets/`. Move the eight files from `src-tauri/icons/` into
`assets/icons/`, trash the empty `src-tauri/`, and check the result with `git diff --stat`. The `.icns` needs macOS
`iconutil`. The MSIX images (M7) are cut from `assets/icons/icon.png` by the same rules as the 1.x
`scripts/package-msix.mjs`.
